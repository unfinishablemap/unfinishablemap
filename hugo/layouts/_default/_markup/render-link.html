{{- /* Link render hook. Its ONLY job beyond Hugo's default is to enrich links into the positions register with tooltip data. Every other link on the site must pass through byte-identical to the default rendering, so the position branch is entered only on an exact match and anything unrecognised falls through. Position links are generated by tools/sync/positions.py in the form /positions//#p-q3 . The fragment is the lookup key into data/positions.yaml, which tools/sync/positions.py regenerates on every sync. Kept to the render-hook API common to Hugo 0.101 (local) and 0.153 (Netlify): .Destination, .Text, .Title only. */ -}} {{- $dest := .Destination -}} {{- $text := .Text -}} {{- $title := .Title -}} {{- $pos := "" -}} {{- if and (hasPrefix $dest "/positions/") (strings.Contains $dest "#") -}} {{- $frag := index (last 1 (split $dest "#")) 0 -}} {{- with site.Data.positions -}} {{- with index . $frag -}} {{- $pos = . -}} {{- end -}} {{- end -}} {{- end -}} {{- if $pos -}} {{- /* `title` carries the whole summary deliberately. Data attributes are dropped by server-side HTML-to-markdown converters (Cloudflare's among them), which keep a link's title as `[text](url "title")` -- so the title is what an agent fetching converted markdown actually receives. It doubles as the no-JavaScript fallback and the screen-reader text. pos-tooltip.js moves it onto a data attribute at init so browsers with JS do not show the native tooltip on top of the hover card. */ -}} {{ $text | safeHTML }} {{- else -}} {{ $text | safeHTML }} {{- end -}}
